# R2 Bucket 容量展示设计

## 1. 背景

当前 GUI 已支持浏览当前 bucket 下的对象列表，并展示每个对象的大小，但还缺少 bucket 级的容量概览。用户目前无法直接判断：

- 当前 bucket 已使用了多少空间
- 距离免费层暂定上限 `10GB` 还有多少余量

本次改动目标是在现有 GUI 中新增一个轻量的容量摘要区，用圆环和文字同时展示当前 bucket 的已用空间情况，并为后续扩展“所有 bucket 合计容量”预留位置。

## 2. 本次目标

- 在对象列表区域上方新增容量摘要区
- 主展示口径为“整个当前 bucket 的已用空间 / 10GB”
- 使用圆环形式展示当前 bucket 使用比例
- 使用文字展示：
  - 当前 bucket 名称
  - 已用空间 / 总空间
  - 已用百分比
  - 所有 bucket 合计占位文案
- 在刷新列表、上传成功、删除成功后同步更新容量摘要

## 3. 非目标

- 本次不统计所有 bucket 的真实合计容量
- 本次不新增独立的容量专用接口
- 本次不把容量统计与搜索关键字绑定
- 本次不实现容量历史趋势、告警、分段配色、动画效果

## 4. 设计决策

### 4.1 展示位置

容量摘要区放在 `gui.py` 中“对象列表”区域的上方，作为列表的摘要信息。

这样做的原因是：

- 容量信息与对象列表属于同一上下文
- 不会挤压底部 URL / 分享链接区域
- 后续如果增加更多 bucket 级信息，也更容易继续扩展

### 4.2 统计口径

当前 bucket 容量统计遵循以下规则：

- 统计范围始终为“当前 bucket 的完整对象列表”
- 不受前缀输入框影响
- 不受搜索关键字影响
- 容量来源为 `list_objects()` 返回的对象 `size`
- 如果单条对象的 `size` 缺失或异常，按 `0` 处理

当当前刷新使用了 `prefix` 时，为了保证容量仍代表“整个 bucket”，允许额外请求一次当前 bucket 的全量对象列表，仅用于容量统计，不影响表格内容。

### 4.3 上限口径

- 总空间上限先固定为免费层暂定值 `10GB`
- 若已用空间超过 `10GB`：
  - 文字显示真实值
  - 圆环显示为满环
  - 百分比可大于 `100%`

## 5. 界面设计

### 5.1 布局

在 `gui.py` 的对象列表区域中，结构调整为：

1. 容量摘要区
2. 对象列表表格
3. 横向与纵向滚动条

容量摘要区内部采用左右布局：

- 左侧：`Canvas` 绘制的圆环
- 右侧：多行文字摘要

### 5.2 展示内容

容量摘要区显示以下内容：

- 当前 bucket：例如 `assets-prod`
- 已用空间：例如 `3.48 GB / 10.00 GB`
- 已用比例：例如 `34.8%`
- 所有 bucket 合计：`暂未统计`

圆环中央显示当前已用空间，便于快速扫视。

### 5.3 视觉约束

- 风格保持与当前 `Tkinter` 界面一致，避免引入过重的卡片式视觉
- 圆环采用两层结构：
  - 底环：浅灰色，表示总容量
  - 前景环：蓝绿色，表示已用容量
- 当前 bucket 未加载数据时显示 `0 B / 10.00 GB`

## 6. 刷新与状态同步

### 6.1 刷新列表成功后

`gui.py` 在刷新对象列表成功后执行以下顺序：

1. 拉取当前表格需要显示的对象列表
2. 如果当前存在 `prefix`，再额外拉取一次当前 bucket 的全量对象列表作为容量统计来源；如果没有 `prefix`，则直接复用当前列表
3. 保存列表数据到内存
4. 基于容量统计来源计算当前 bucket 总字节数
5. 更新容量文字摘要
6. 重绘容量圆环
7. 再执行搜索过滤与表格渲染

### 6.2 上传成功后

上传成功后继续沿用现有 `refresh_objects()` 刷新流程，由刷新后的结果统一更新容量摘要。

为了让界面反馈更快，如果当前 bucket 的容量快照已存在，可以基于本次上传文件大小先做一次本地即时更新，再以刷新结果校准。

### 6.3 删除成功后

删除成功后继续沿用现有刷新流程，以刷新后的列表结果为准更新容量摘要。

为了让界面反馈更快，如果当前 bucket 的容量快照已存在，可以基于已删除对象的缓存大小先做一次本地即时更新，再以刷新结果校准。

### 6.4 切换 bucket

- 仅切换 bucket 但未刷新前，容量摘要显示该 bucket 的默认空状态
- 刷新成功后再显示真实容量

### 6.5 刷新失败

- 保留上一次成功加载的容量显示
- 不主动清零
- 避免用户误以为 bucket 当前为空

## 7. 代码结构调整

### 7.1 `gui.py`

新增或调整以下职责：

- 新增容量摘要区 UI
- 新增容量相关状态字段
- 新增容量统计、格式化、绘制方法
- 在对象列表数据变化后统一触发容量摘要刷新

建议新增的方法职责如下：

- 计算当前 bucket 总字节数
- 计算容量比例
- 刷新容量文字
- 重绘圆环
- 刷新容量摘要区整体状态

### 7.2 `r2_client.py`

本次不新增接口。

原因：

- 当前 `list_objects()` 已返回对象 `size`
- 当前需求只依赖现有对象列表数据即可完成

## 8. 边界情况

- 当前没有 bucket：显示空状态
- 当前 bucket 为空：显示 `0 B / 10.00 GB`
- 当前 bucket 容量超过 `10GB`：文字显示真实值，圆环满环
- 单条对象缺失 `size`：按 `0` 处理
- 搜索关键字变化：容量摘要不变
- 前缀变化但未刷新：容量摘要不变

## 9. 测试范围

手动验证至少覆盖以下场景：

- 空 bucket 显示
- 少量对象 bucket 显示
- 接近 `10GB` 的显示
- 超过 `10GB` 的显示
- 搜索关键字变化时容量摘要不变
- 前缀输入存在时，容量摘要仍代表整个 bucket
- 刷新成功后容量摘要正确更新
- 上传成功后容量摘要正确更新
- 删除成功后容量摘要正确更新
- 刷新失败时保留上一次成功容量状态
- 窗口缩放后摘要区与列表布局保持可用

## 10. 后续扩展

后续可以在当前设计基础上继续扩展：

- 真实统计所有 bucket 合计容量
- 把总容量上限改为配置项
- 为不同容量区间增加颜色变化
- 增加“当前前缀范围容量”辅助信息
