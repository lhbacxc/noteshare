# 上传错误日志与日志等级设计

## 背景

当前上传失败时，桌面端会在上传状态区显示“上传失败”，并弹出错误提示框。这个反馈适合当场处理，但用户一旦关闭弹窗，就缺少可回看的错误记录，后续排查网络、权限、bucket、对象 Key 或 multipart 断点问题时不够方便。

本次目标是在不改变现有上传主流程的前提下，增加本地日志文件，并允许用户在界面中选择日志等级。

## 功能目标

- 在连接配置区新增“日志等级”下拉框。
- 支持三个等级：
  - `全部`：记录普通运行信息、警告和错误。
  - `警告`：只记录警告和错误。
  - `错误`：只记录错误。
- 默认等级为 `错误`，避免日常使用时产生过多日志。
- 日志配置随 `config.json` 保存，保存配置后立即生效。
- 日志文件固定写入 `logs/noteshare.log`。
- 日志文件使用 UTF-8 编码和滚动写入，避免长期使用后单个日志无限增大。

## 记录范围

本轮优先记录和排查上传相关的高价值信息：

- 应用启动和日志等级生效。
- 上传任务开始、上传成功、上传暂停、上传取消。
- 上传失败，包括 bucket、本地文件、对象 Key、文件大小和异常堆栈。
- 静态断点取消失败。
- 通用后台任务失败，作为非上传操作的兜底错误记录。

暂停和取消属于用户主动操作，不按错误记录；只有清理断点失败、R2 请求失败或其他异常才写入错误日志。

## 数据与配置

`config.json` 新增字段：

```json
{
  "log_level": "error"
}
```

可选值为：

- `all`
- `warning`
- `error`

历史配置没有该字段时自动回退为 `error`。如果字段值异常，也自动清洗为 `error`。

## 实现结构

新增 `app_logger.py`，集中负责：

- 日志等级清洗。
- 日志等级标签与配置值互相转换。
- 初始化 `logging` 的 `RotatingFileHandler`。
- 暴露 `get_app_logger()` 供界面和业务代码使用。

`pyside6_ui/main_window.py` 只负责：

- 在配置区展示下拉框。
- 读写 `log_level`。
- 在关键上传流程调用 logger。

## 错误处理

- 如果日志目录创建或日志文件写入失败，不阻塞主业务流程。
- 日志初始化失败时不弹窗，避免“记录错误的功能本身”影响上传。
- 用户界面仍保留现有错误弹窗和上传状态区提示；日志是补充排查信息，不替代可见反馈。

## 验证方式

- `python -m py_compile` 验证新增模块和主窗口代码。
- 离屏实例化 `NoteShareMainWindow`，确认日志等级下拉框可加载。
- 手动调用日志初始化并写入测试错误，确认 `logs/noteshare.log` 生成且内容为 UTF-8。
