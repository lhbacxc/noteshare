# 上传进度与网速显示设计

## 背景

当前桌面端已经支持通过文件选择和拖拽上传本地文件到 Cloudflare R2，但上传过程中只在状态栏显示“正在上传文件...”，用户无法判断大文件上传进度、当前网速或多文件上传是否仍在推进。

## 目标

- 在上传文件时展示可见进度条。
- 展示已上传大小、总大小、百分比和当前上传速度。
- 多文件上传时按本次任务的总字节数汇总进度，并显示当前正在上传第几个文件。
- 复用现有 `boto3 upload_file` 上传链路，不重写手工分片上传。
- 保持界面结构克制，不新增独立上传窗口。

## 非目标

- 不实现上传暂停、继续、取消。
- 不实现后台上传队列和历史任务列表。
- 不改变 Cloudflare R2、Worker 或分享链接链路。
- 不改变单文件上传大小边界。

## 方案

在“对象操作”卡片底部增加一个紧凑上传状态区：

- 默认显示“待上传”。
- 上传开始后显示当前文件名和 `第 n/m 个文件`。
- 进度条显示本次上传任务的总进度。
- 详情文本显示 `百分比 · 已上传 / 总大小 · 当前速度`。
- 上传成功后显示完成摘要。
- 上传失败后保留失败状态，并通过原有错误弹窗提示原因。

上传进度来源于 `boto3.client.upload_file` 的 `Callback` 参数。该回调会在底层传输过程中报告本次新增上传字节数，因此可以在后台线程中累计已传字节，再通过 Qt signal 把进度数据推回主线程刷新 UI。

网速按最近一次界面刷新间隔内上传的字节数计算，并做节流刷新，避免进度信号过于频繁导致界面抖动。

## 数据流

1. 用户通过按钮或拖拽选择本地文件。
2. 主窗口确认每个文件的对象 Key，并统计本次任务总字节数。
3. 后台任务逐个调用 `R2Manager.upload_file`。
4. `R2Manager.upload_file` 将进度回调传给 `boto3 upload_file`。
5. 回调累计总上传字节数、当前文件字节数和最近速度。
6. 后台线程通过 Qt signal 发送进度快照。
7. 主线程更新上传状态区与状态栏。
8. 上传完成后刷新对象列表与 bucket 容量摘要。

## 错误处理

- 本地文件不存在或不是文件时沿用现有提示。
- 上传过程中出现 R2 或网络错误时，保持原有错误弹窗，同时将上传状态区切换为失败状态。
- 如果总大小为 0，进度条显示为 100%，速度显示为 `0 B/s`。

## 验证

- 执行 `python -m py_compile app.py r2_client.py pyside6_ui/main_window.py pyside6_ui/tasks.py`。
- 使用离屏方式实例化 `NoteShareMainWindow`，确认新增控件不会破坏启动。
- 使用一个模拟 R2 manager 调用上传流程中的进度更新方法，确认进度条、大小和速度文本能正常刷新。
