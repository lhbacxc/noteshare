# PySide6 UI 渐进迁移设计

## 1. 背景

当前项目使用 `Tkinter` 构建本地桌面 GUI，已经具备以下较完整的本地管理能力：

- R2 连接配置保存与加载
- bucket 加载与切换
- 对象列表浏览、搜索、前缀过滤
- 上传、下载、删除对象
- 预签名 URL 生成与复制
- 可撤销分享创建、停止、复制
- bucket 容量概览与圆环展示
- 启动自动刷新与本地倒计时刷新

随着功能增多，当前 `Tkinter` 界面在视觉层次、交互组织和后续扩展性上都开始显得吃力。用户希望：

- 在不影响 `main` 分支的前提下，在 `pyside6UI` 分支内进行迁移和测试
- 新界面使用 `PySide6`
- 迁移期间保留现有 `Tkinter` 入口
- 目标是尽量完整覆盖当前 Tkinter 版本功能
- 界面风格偏现代轻量化
- 本轮先保证开发启动和分支内测试，不把打包作为阻塞项

## 2. 目标

本次迁移的目标不是只做一个静态原型，而是在当前分支中建立一套可逐步替代 Tkinter 的 `PySide6` 界面层。

本次目标：

- 保留现有 `Tkinter` 入口可运行
- 新增 `PySide6` 开发入口
- 尽量复用现有业务模块
- 将当前高频功能逐步迁移到 `PySide6`
- 让新界面具备更清晰的信息层级与更现代的视觉结构
- 为后续彻底切换默认 GUI 做准备

本次非目标：

- 本轮不优先处理 `PyInstaller` 打包适配
- 本轮不重写 `r2_client.py`、`worker_client.py`、`config_manager.py` 的底层业务接口
- 本轮不引入过重的完整 MVVM 框架
- 本轮不追求和 Tkinter 版逐像素一致

## 3. 迁移策略

采用“渐进式双栈迁移”方案。

### 3.1 原则

- 保留旧入口，新增新入口
- 业务层优先复用，界面层独立重建
- 先搭好可运行骨架，再逐步补齐功能
- 不把现有 Tkinter 中的高耦合结构原样复制到 PySide6

### 3.2 方案说明

- `app.py` 继续保留为当前 `Tkinter` 入口
- 新增 `app_pyside6.py` 作为 `PySide6` 开发入口
- 现有下列模块继续作为共享业务层：
  - `config_manager.py`
  - `r2_client.py`
  - `worker_client.py`
- 新增一组 `PySide6` 专用 UI 模块，用于承载新界面、状态管理与线程任务

### 3.3 方案优势

- 不影响当前 Tkinter 版本继续运行
- 可以在同一份配置和同一套业务逻辑下对照验证
- 降低“界面迁移”和“业务回归”同时爆炸的风险
- 后续如果需要切换默认入口，只需调整入口指向，不必重做业务层

## 4. 建议目录结构

建议新增目录：

```text
.
├── app.py
├── app_pyside6.py
├── gui.py
├── config_manager.py
├── r2_client.py
├── worker_client.py
└── pyside6_ui/
    ├── __init__.py
    ├── main_window.py
    ├── state.py
    ├── tasks.py
    ├── theme.py
    ├── widgets/
    │   ├── object_table.py
    │   ├── detail_panel.py
    │   ├── storage_ring.py
    │   └── config_bar.py
    └── dialogs/
        ├── expire_dialog.py
        └── object_key_dialog.py
```

说明：

- `main_window.py`：主窗口、主布局、全局动作协调
- `state.py`：集中保存界面状态，避免状态散落在控件内部
- `tasks.py`：后台任务封装，统一线程与回调处理
- `theme.py`：颜色、间距、字号、控件样式等主题常量
- `widgets/`：拆分主要界面组件，避免再次形成超大 GUI 文件
- `dialogs/`：承载设置过期秒数、上传对象名输入等对话框

## 5. 主界面设计

新界面采用“现代轻量化管理台”风格，但核心仍是效率优先的桌面工具，不做过度装饰。

### 5.1 整体布局

主窗口拆为四个区域：

1. 顶部连接栏
2. 左侧对象主区
3. 右侧详情面板
4. 底部状态栏

### 5.2 顶部连接栏

顶部连接栏负责展示和编辑全局连接信息，同时承载最常用的全局操作。

建议包含：

- `Account ID`
- `Access Key ID`
- `Secret Access Key`
- `Endpoint URL`
- `Worker Base URL`
- `Worker Admin Token`
- `Bucket`
- `保存配置`
- `测试连接`
- `加载 Bucket`

设计要求：

- 采用更扁平的工具栏式编排，而不是厚重的大块表单
- 支持响应式换行，避免窗口缩小时完全挤压失真
- 密钥类字段默认隐藏

### 5.3 左侧对象主区

左侧区域是主工作区，重点承载对象浏览与批量操作。

上方为筛选条：

- `前缀`
- `搜索`
- `刷新列表`

下方为对象表格，保留当前关键列：

- `Key`
- `Size`
- `Last Modified`
- `Storage Class`
- `默认过期秒数`
- `URL 到期 / 剩余时间`

设计要求：

- 支持列宽调整
- 支持单选和多选
- 选中态清晰
- 为后续加入排序和右键菜单保留空间

### 5.4 右侧详情面板

右侧详情面板负责集中展示“当前选中对象的上下文信息”，避免当前 Tkinter 版本中信息分散在底部和列表附近的问题。

建议包括：

- 当前选中文件基本信息
- 当前有效预签名 URL
- 当前有效分享链接
- 分享状态与过期信息
- bucket 容量概览
- 与当前选中对象相关的快捷操作按钮

设计要求：

- 左侧表格负责浏览，右侧面板负责详情与当前对象操作
- 空状态下显示占位提示，不报错
- URL 和分享链接区域支持复制动作

### 5.5 底部状态栏

底部状态栏用于展示：

- 当前状态文本
- 后台任务进行中提示
- 轻量成功反馈
- 轻量失败反馈

设计要求：

- 尽量减少成功类弹窗
- 普通失败优先走状态栏或非阻塞提示
- 仅高风险或无法继续的场景使用阻塞弹窗

## 6. 功能迁移范围

### 6.1 阶段一：骨架可运行

目标：确保 `PySide6` 入口、主窗口和基础状态可以稳定启动。

包括：

- 新增 `app_pyside6.py`
- 新增 `pyside6_ui/` 基础结构
- 主窗口框架与布局
- 读取现有 `config.json`
- 初始化基础主题和状态栏
- 确保新旧入口可以并存运行

### 6.2 阶段二：核心业务可用

目标：覆盖最常用的日常高频操作。

包括：

- 保存配置
- 测试连接
- 加载 bucket
- 刷新对象列表
- 搜索与前缀过滤
- 选中对象后刷新右侧详情
- 生成预签名 URL
- 复制 URL
- 创建可撤销分享
- 停止分享
- 复制分享链接
- bucket 容量统计与圆环展示

### 6.3 阶段三：完整替代能力

目标：尽量接近当前 Tkinter 版本的完整可替代状态。

包括：

- 上传文件
- 下载选中对象
- 删除单个或多个对象
- 设置选中文件默认过期秒数
- 启动自动加载和自动刷新
- 每 5 秒本地倒计时刷新
- 更细粒度的错误提示
- 与现有配置格式兼容的状态持久化

## 7. 状态管理设计

`PySide6` 版本不再让控件各自持有零散状态，而是引入一份轻量集中状态。

建议状态内容包括：

- 当前配置数据
- 当前 bucket
- 全量对象列表
- 过滤后对象列表
- 当前选中对象 key 列表
- 当前展示中的有效 URL
- 当前展示中的有效分享链接
- 当前容量快照
- 当前后台任务状态

设计要求：

- 主窗口、对象表格、详情面板从统一状态刷新
- 选择变化、过滤变化、任务完成后统一走状态同步
- 不允许多个控件各自偷偷维护同一字段的副本

## 8. 后台任务与线程模型

迁移到 `PySide6` 后，继续坚持“耗时操作不阻塞主线程”。

### 8.1 统一任务封装

以下操作统一走后台任务层：

- 测试连接
- 加载 bucket
- 刷新对象列表
- 上传
- 下载
- 删除
- 生成预签名 URL
- 创建分享
- 停止分享

### 8.2 主线程职责

主线程仅负责：

- 界面渲染
- 控件状态切换
- 接收任务成功或失败信号
- 根据结果刷新状态和界面

### 8.3 任务反馈

后台任务需要统一提供：

- 开始状态通知
- 成功结果回调
- 失败结果回调
- 结束后的按钮状态恢复

## 9. 错误处理设计

错误处理分三级：

### 9.1 状态栏提示

用于普通成功、普通失败、复制完成、刷新完成等轻量反馈。

### 9.2 非阻塞提示

用于用户需要注意但不一定要立刻打断流程的提示，例如：

- URL 已生成
- 分享已停止
- 文件已下载

### 9.3 阻塞弹窗

仅用于：

- 删除确认
- 必填配置缺失
- 严重连接错误
- 当前操作无法继续的异常

补充要求：

- 避免把所有结果都做成 `messagebox` 风格的阻塞体验
- 保留当前 Tkinter 版本里已经验证过的关键异常信息
- 继续兼容 `Worker` 返回的错误文本展示

## 10. 定时刷新与自动加载

以下现有行为在 `PySide6` 版本中应保留：

- 启动时自动尝试加载最近使用 bucket
- 在可自动加载的条件满足时执行自动刷新
- 每 5 秒本地刷新一次 URL 剩余时间显示

实现建议：

- 使用 `QTimer` 实现本地倒计时刷新
- 使用窗口初始化流程替代 Tkinter `after` 组织方式
- 自动刷新失败时给出温和反馈，不阻断整个界面启动

## 11. 验收标准

### 11.1 启动与基础状态

- `python app.py` 仍可启动 Tkinter 版本
- `python app_pyside6.py` 可启动 PySide6 版本
- PySide6 版本能读取现有 `config.json`
- 启动时不会因缺少 Worker 配置或未选 bucket 而直接崩溃

### 11.2 核心业务链路

- 测试连接成功
- 加载 bucket 成功
- 刷新对象列表成功
- 搜索与前缀过滤正确
- 选中对象后右侧详情同步正确
- 生成预签名 URL 与复制 URL 可用
- 创建可撤销分享、停止分享、复制分享链接可用
- bucket 容量统计与圆环展示正确

### 11.3 完整替代能力

- 上传可用
- 下载可用
- 删除可用且带确认
- 设置默认过期秒数可用
- URL 剩余时间本地刷新可用
- 启动自动加载与自动刷新行为基本符合旧版

### 11.4 稳定性与体验

- 网络请求期间界面不假死
- 任务执行时按钮禁用和状态提示合理
- 错误提示不全部退化为阻塞弹窗
- 常见异常场景下仍能继续操作
- 在相同配置下，新旧版本核心行为基本一致

## 12. 实施顺序

推荐实际落地顺序如下：

1. 增加 `PySide6` 依赖与新入口
2. 搭建 `pyside6_ui/` 基础目录
3. 完成主窗口骨架和主题
4. 接通配置加载、保存、测试连接、加载 bucket
5. 接通对象列表、搜索、前缀过滤、详情同步
6. 接通 URL / 分享 / 容量相关功能
7. 接通上传、下载、删除、设置过期秒数
8. 补齐自动刷新、倒计时与错误处理
9. 与 Tkinter 版本做对照验证

## 13. 风险与注意事项

- 当前 Tkinter 版本把较多职责集中在 `gui.py`，迁移时要避免复制出一个同样臃肿的 `PySide6` 文件
- `PySide6` 引入后，依赖、启动方式和后续打包方式都会变化，但本轮先不把打包作为阻塞项
- 当前工作区存在一个未提交的 `README.md` 删除状态，本次迁移和提交不应误包含该变更
- 如果分阶段迁移中发现某些 Tkinter 行为本身不理想，应优先修正为更合理的 `PySide6` 体验，而不是机械复刻

## 14. 完成定义

本次分支内迁移完成的定义为：

- Tkinter 与 PySide6 双入口并存
- PySide6 版本能覆盖主要日常使用流程
- 现有共享业务模块继续复用
- 新界面结构较清晰，可继续扩展
- 后续如果决定切换默认 GUI，只需要调整入口与少量兼容收尾
