# 断点续传设计

## 背景

当前上传链路已经支持拖拽上传、进度显示、实时网速和取消上传，但还需要区分“主动暂停”和“明确取消”。大文件上传时，用户希望暂停后可以继续，暂停后关闭客户端也能在下次启动时继续；网络失败后可以重试续传；取消上传则视为放弃本次上传，下次重新开始。

本次目标是在不改变现有主界面结构的前提下，为本地 GUI 上传增加断点续传、暂停上传和继续上传能力。

## 设计目标

- 点击“暂停上传”后保留未完成上传的恢复状态，点击“继续上传”时自动复用断点。
- 暂停后关闭客户端不清理断点；下次启动时自动读取本地断点状态，并在上传状态区显示可继续上传的文件。
- 网络异常或 R2 / boto3 错误导致上传失败后保留断点，用户可点击“继续上传”，也可下次重新选择同一本地文件和同一 `bucket + object key` 后续传。
- 点击“取消上传”时清理本次断点，下次上传同一文件时重新开始。
- 上传成功后自动清理对应断点状态，避免状态文件长期堆积。
- 保留现有单上传任务约束、进度条、网速显示和取消上传交互，并新增暂停/继续按钮。
- 正式文档继续使用相对路径说明改动。

## 非目标

- 不新增上传任务列表。
- 不做跨设备恢复。
- 不做多个历史断点的可视化管理。
- 不把取消上传设计成可恢复操作；取消代表放弃本次断点。
- 不支持本地文件发生变化后的强制续传；文件路径、大小或修改时间变化后视为新上传。

## 技术方案

### R2 上传层

在 `r2_client.py` 中新增 resumable multipart 上传方法，直接使用 S3 兼容接口：

- `create_multipart_upload`
- `list_parts`
- `upload_part`
- `complete_multipart_upload`

上传开始时优先读取本地断点状态中的 `upload_id`。如果远端仍能列出该 multipart upload 的已完成 part，则跳过这些 part；如果远端会话已经失效，则自动创建新的 multipart upload。

分片大小按文件大小动态计算，默认不低于 `64 MiB`，并保证大文件不会超过 S3 multipart 的 10000 part 上限。

### 本地状态

新增 `upload_resume_store.py`，在程序运行目录保存 `upload_resume_state.json`。状态文件不纳入 Git，内容只保存恢复上传所需信息：

- endpoint
- bucket
- object key
- 本地文件路径
- 本地文件大小和修改时间
- upload id
- part size
- 已完成 part 的 `PartNumber`、`ETag` 和大小

状态 key 由 endpoint、bucket、object key、本地文件路径、文件大小和修改时间生成。只要本地文件发生变化，就不会误用旧断点。

本地状态文件没有主动过期时间，暂停后关闭客户端也会继续保留。真正影响续传时限的是远端 multipart upload 生命周期：Cloudflare R2 默认会在 7 天后自动中止未完成的 multipart upload。超过远端生命周期后，本地记录仍可能存在，但客户端列不到远端已完成 part，会自动创建新的 multipart upload，也就是从头重新上传。

### GUI 上传链路

`pyside6_ui/main_window.py` 继续使用现有上传任务入口。用户先确认本地文件与对象 Key，再由后台任务读取断点状态并传给 R2 上传层：

- 上传中显示“暂停上传”和“取消上传”。
- 暂停后显示“继续上传”，继续时复用已确认的本地路径和对象 Key，不再重复弹 Key 确认框。
- 启动时会扫描 `upload_resume_state.json`，如果本地文件仍存在且大小匹配，就在上传状态区显示“发现可继续上传”。
- 有断点状态时，状态区文案显示“断点续传”。
- R2 上传层发现已有远端 part 后，把已完成字节数计入当前进度。
- 当真正开始传输后续未完成 part 时，状态区文案切回“正在上传”。
- 暂停上传或网络异常上传失败时保留状态。
- 暂停后再关闭客户端时，窗口等待暂停流程收尾并保留断点，不把这次关闭改判为取消上传。
- 取消上传时删除本地断点，并尽量调用 `abort_multipart_upload` 清理远端未完成 multipart upload。
- 上传成功后删除对应状态。

## 错误处理

- 本地状态文件损坏时忽略并重建，不阻塞上传。
- 远端 multipart upload 已失效时自动重新创建上传会话。
- 取消上传仍使用现有取消状态，不弹出普通失败错误。
- 暂停上传不弹普通失败错误，只更新为“上传已暂停，可继续上传”。
- 如果 botocore 把暂停/取消异常包装成 `HTTPClientError`，R2 层会还原成专门的上传中断状态，避免弹出 `An HTTP Client raised an unhandled exception`。
- 其他 R2 / boto3 错误保持现有错误弹窗行为，同时保留断点状态供下次重试。
