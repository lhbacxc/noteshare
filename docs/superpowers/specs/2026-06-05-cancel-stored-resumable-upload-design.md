# 重启后取消已暂停上传任务设计

## 背景

当上传任务暂停后关闭客户端，重启时 GUI 会从 `upload_resume_state.json` 读取断点状态，并在上传状态区显示“发现可继续上传”。当前此状态只启用了“继续上传”，而“取消上传”仍然依赖正在运行的后台上传线程，因此用户点击取消没有实际效果。

## 目标

- 重启后发现可继续上传任务时，“取消上传”也必须可用。
- 用户点击取消后，应清理本地断点状态，并尽量中止远端未完成 multipart upload。
- 如果远端中止失败，需要明确提示错误；不能表现为按钮无反应。

## 方案

在 `_request_cancel_upload()` 中区分两种状态：

- 正在上传：继续走现有 `_stop_upload("cancel")`，由后台线程收尾。
- 未在上传但存在 `_resume_upload_items` 与 `_resume_upload_bucket`：走新增的 `_cancel_stored_resumable_upload()`，创建 `R2Manager`，复用 `_cleanup_upload_sessions()` 清理本地断点并尽量 abort 远端 upload，然后清空恢复任务状态并刷新上传状态区。

启动加载断点任务时，同时启用“继续上传”和“取消上传”按钮。

## 验证

- 通过 `py_compile` 验证语法。
- 离屏模拟重启后的可继续任务，验证取消按钮可用。
- 离屏调用取消逻辑，验证本地恢复任务状态被清空，继续/取消按钮被禁用，状态区变为“上传已取消”。
