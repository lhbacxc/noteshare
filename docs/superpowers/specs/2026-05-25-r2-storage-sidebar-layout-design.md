# R2 容量侧栏布局调整设计

## 1. 背景

当前对象列表区已经加入容量圆环和摘要信息，但采用的是“列表上方摘要区”的布局。实际使用中，这会明显压缩下方文件列表的可见高度，影响浏览体验。

本次调整目标是在不改变容量统计口径的前提下，把容量展示改为“左侧文件列表，右侧容量栏”的两列结构，让文件列表重新获得更完整的垂直空间。

## 2. 本次目标

- 把对象列表区从“上下结构”改为“左右两列结构”
- 左侧保留文件列表为主内容区
- 右侧改为容量信息侧栏
- 右侧侧栏在窗口缩小时适度压缩，优先让空间给文件列表
- 缩小圆环尺寸，降低视觉占用

## 3. 非目标

- 本次不修改容量统计口径
- 本次不新增“所有 bucket 合计”的真实统计
- 本次不增加自动切换回上下布局的响应式逻辑
- 本次不重做对象列表列结构和文件操作区

## 4. 布局决策

### 4.1 整体结构

`gui.py` 中的对象列表区调整为两列：

1. 左列：文件列表区
2. 右列：容量侧栏

左列作为主内容区，占据主要宽度；右列作为辅助信息区，仅承载容量展示。

### 4.2 左列内容

左列保留原有对象列表相关控件：

- `Treeview`
- 纵向滚动条
- 横向滚动条

这样可以最大程度复用当前列表逻辑，只调整承载它们的布局容器。

### 4.3 右列内容

右列容量侧栏承载以下内容：

- 缩小后的容量圆环
- 当前 bucket 名称
- 已用空间 / 总空间
- 已用比例
- “所有 bucket 合计：暂未统计”

右栏仍然只展示当前 bucket 的容量概览，不和文件选择状态耦合。

## 5. 宽度与缩放策略

### 5.1 宽度策略

- 左列设置更高的伸缩权重
- 右列设置较小的推荐宽度
- 右列设置最小可接受宽度，避免内容完全挤坏

### 5.2 缩放行为

窗口缩小时采用以下优先级：

1. 先压缩右侧容量栏宽度
2. 再尽量保持左侧文件列表宽度
3. 不自动切回上下布局

这样可以更符合“文件列表优先”的使用诉求。

## 6. 视觉约束

- 圆环尺寸较当前版本缩小一档
- 右栏整体更像轻量信息侧栏，而不是大卡片
- 文案行高更紧凑
- 右栏弱化空白留白，避免视觉浪费

## 7. 数据与交互

本次不调整以下逻辑：

- 当前 bucket 容量始终表示“整个 bucket 的已用空间 / 10GB”
- 搜索关键字变化不影响容量显示
- 使用 `prefix` 刷新时，容量仍然基于整个 bucket 统计
- 上传成功、删除成功后仍先做本地即时更新，再用刷新结果校准
- 刷新失败时保留上一次成功容量状态

也就是说，这次改动的重点是布局承载位置，而不是容量逻辑本身。

## 8. 代码结构调整

主要改动集中在 `gui.py`：

- 重排对象列表区内部容器
- 把原先位于列表上方的容量摘要区迁移到右侧侧栏
- 调整圆环尺寸与侧栏文案布局
- 保持现有容量刷新方法可复用

`r2_client.py` 与配置相关模块本次无需改动。

## 9. 验证范围

手动验证至少覆盖以下场景：

- 文件列表高度明显恢复
- 右侧容量栏不再占据文件列表垂直空间
- 窗口缩小时，右栏先压缩，列表优先保留空间
- 圆环与文案在较窄宽度下不重叠
- 刷新、上传、删除后三种路径仍会正确更新容量栏
- `prefix` 存在时，右栏仍表示整个 bucket 容量
- 没有 bucket 或刷新失败时，右栏空状态与保留策略正常

## 10. 后续扩展

后续如果仍然觉得右栏在窄窗口下占用偏大，可以继续扩展：

- 在非常窄的宽度下切回上下布局
- 提供“折叠容量侧栏”开关
- 把右栏改为更紧凑的迷你信息卡
