# 上传暂停与取消收尾进度反馈设计

## 背景

当前上传过程中点击“暂停上传”或“取消上传”后，界面会把标题切换为“正在暂停上传”或“正在取消上传”，但原有确定进度条停留在点击前的位置。由于后台仍需要等待当前 multipart 分片返回、保存断点或清理断点，用户容易误以为客户端已经卡住。

## 目标

- 暂停/取消请求发出后，上传状态区必须持续给出“仍在处理”的视觉反馈。
- 不新增独立弹窗，不改变现有对象操作区布局。
- 后台真正进入已暂停、已取消、失败或完成状态后，进度条必须恢复为确定进度状态。

## 方案

复用现有 `QProgressBar`。上传正常推进时继续使用 `0-1000` 的确定进度；点击暂停或取消后，将同一条进度条切换为 `0-0` 的忙碌态，标题和详情文案说明正在等待当前分片响应、保存断点或清理断点。

当后台任务结束后，由已有的 `_mark_upload_paused()`、`_mark_upload_cancelled()`、`_mark_upload_complete()` 和 `_mark_upload_failed()` 统一恢复确定进度条，避免忙碌态残留。

## 验证

- 通过 `py_compile` 验证语法。
- 离屏实例化主窗口。
- 离屏模拟上传中点击暂停/取消，验证进度条会进入忙碌态，并在暂停/取消完成标记后恢复确定态。
